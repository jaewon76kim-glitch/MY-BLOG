## 이 앱의 성격 — 검증 우선순위

**이 앱의 가치는 전적으로 스펙 정보의 정확도에 달려 있습니다.** 사용자는 25년 경력의 3GPP 단말 프로토콜 개발자로, 번호나 명칭이 틀리면 즉시 알아봅니다. 따라서:

**최우선 — 스펙 정보 정확성 (가장 많은 시간을 여기 쓸 것)**

`js/specs.js`의 각 항목에 대해 WebSearch/WebFetch로 대조하십시오. 특히:

1. **스펙 번호 ↔ 정식 명칭(`title`) 일치** — 번호는 맞는데 제목이 다른 문서인 경우가 가장 위험
2. **계층 배치(`m` 필드)가 맞는가** — 예: 37.324(SDAP)가 37.xxx 시리즈인 것이 맞는지
3. **`peer`(LTE↔NR 대응)가 실제 대응 관계인가**
4. **`rel`(도입 릴리스)이 맞는가**
5. **`ntn` 표시** — 'only'로 표시된 5개(38.101-5, 38.108, 38.811, 38.821, 36.763)가 정말 NTN 전용인지, 'clause'로 표시된 9개에 실제로 NTN 조항이 있는지
6. **`tr` 플래그** — TR(연구문서)과 TS(규격)를 바르게 구분했는지. 38.811/38.821/36.763/38.822가 TR로 표시됨
7. **누락된 중요 스펙** — 단말 프로토콜 개발자 관점에서 반드시 있어야 하는데 빠진 것

특별히 확인할 주장 두 가지 (앱이 명시적으로 강조하는 내용이라 틀리면 치명적):
- **RRM 비대칭**: LTE는 `36.521-3`(521 시리즈 안), NR은 `38.533`(521 밖)이라는 주장
- **38.213 vs 36.213**: NR은 제어(38.213)/데이터(38.214)로 분리, LTE는 36.213 하나로 통합이라는 주장

**차선 — 동작 검증**

`python3 -m http.server`로 띄운 뒤 실제 브라우저에서:
- Level 0 스택도 렌더링, 각 계층/기둥 클릭 → Level 1 진입
- 뒤로가기 버튼과 브라우저 뒤로가기(해시 라우팅) 모두 동작
- 검색: "38.331", "RACH", "도플러" 입력 시 결과
- "NTN만" 토글
- 카드의 `대응: 36.331` 링크 클릭 → 해당 스펙으로 이동 + 하이라이트
- 모바일 폭 360px에서 레이아웃 붕괴 없는지
- 다크모드(`data-theme="dark"`) 적용 확인
- 콘솔 에러 0건
